# Pixflow Frontend

Use the brief, audience, existing identity and selected styling mode to decide the visual direction. A focused edit retains its scope; an administrative request does not become a design exercise. The agent chooses useful references and tools.

- [Design Taste, adapted for Pixflow](references/design-taste.md) offers composition, typography, imagery and interaction decisions for new designs and redesigns.
- [Rendered quality](references/quality-review.md) helps evaluate actual output, including inherited styles and states a hero screenshot cannot show.
- Read the site's existing typography, colours and reusable resources before changing its identity. Preserve existing content and styling outside the requested scope.
- Discover available execution guidance through `skills.list`. When a Pro builder integration or design-system manager is available, read its matching guidance before using it. Those optional guides are supplied by Pro; do not assume their files or tools exist in Free, and do not substitute another builder's workflow.
- Use the active editor's native content, styling, history and save tools. Reuse supplied site context rather than rediscovering resources. Reusable styles own shared presentation; native element fields own content and behaviour.
- Use available media tools and existing WordPress uploads when relevant. Preserve image metadata and verify the rendered result; optional stock or generation tools must be discovered before use.

These links are maintained Pixflow guidance. Upstream attribution is provenance, not an instruction to fetch or invoke another skill. No additional design stack, mandatory planning document, approval step or fixed tool sequence is introduced. Research remains available when the brief or missing information calls for it.
