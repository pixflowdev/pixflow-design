# Web composition reference

Use the brief and selected design system to choose a composition. The bundled `example.html`, `assets/template.html` and `references/layouts.md` offer examples, not a required sequence or fixed layout inventory.

For a Bricks request, create native editable elements in the active builder. Use the maintained Pixflow Frontend and Bricks live-builder guidance for classes, selected token mode, hydration, follower feedback and saving. HTML examples are visual references, not a reason to switch execution to an HTML artifact or server-side replacement. Existing site fonts and customer brand preferences take precedence over the seed's typography and palette.

For a requested standalone HTML prototype, the seed can save time. Adapt its sections and tokens to the content; add layouts and components when they suit the brief. No fixed accent budget, font family or section rhythm applies to every project.

Use real approved or generated imagery where it helps. Bring website media into WordPress through the relevant media skill. Do not retain placeholder images as completed work or invent testimonials, statistics or product claims.

Review the rendered result for readable contrast, responsive layout, meaningful links and usable controls. Fix observed problems in the same run. The checklist provides review topics; it does not require a preliminary report, score, approval or separate phase.

Return a concise account of the result and any unverified limitations. Preserve the requested output surface and scope.
