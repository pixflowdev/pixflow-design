# Maintenance priorities

The public source maintenance priorities are independent Free validation, stable shared contracts, compatible optional Pro pairing and preservation of existing user data. Current work should follow repository instructions and scoped issue/test evidence rather than an inherited Open Design launch schedule.

Changes to shared browser/Bridge behavior must preserve both UI and CLI access, native editor state and authenticated recovery. Packaging work must preserve installed basenames, channel identity and immutable published artifacts. Language changes retain complete source locales and existing language preferences.

Private operational plans and local acceptance receipts are not public feature commitments. A proposed feature is not available until its implementation, required surfaces and relevant validation are complete. Product/API behavior is documented in [scope](spec.md), [architecture](architecture.md) and the owning module guides.
