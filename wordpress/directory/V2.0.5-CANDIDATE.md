# Pixflow Design v2.0.5 directory candidate

This is a new directory candidate, not a replacement for the published v2.0.4 plugin, Pro add-on or Bridge installers. The installed plugin identity remains `pixflow-ai/pixflow-ai.php`. The directory build omits the website updater and its Update URI. The website build profile is unchanged.

## Compatibility checks

- Isolated WordPress upgrades from 2.0.2, 2.0.3 and the published 2.0.4, with saved licences and legacy history. Content, settings, personal skills and message fields were compared before/after. Update offers use test metadata; this does not claim the candidate is already available on WordPress.org.
- Published Pro 2.0.4 activates with the saved licence. Its Workspace opens older text-based chats through the shared API adapter without rewriting stored messages. The regression test is `wordpress/tests/workspace-legacy-message.test.php`.
- Published Windows Bridge 2.0.4 CLI authenticates, reads context/capabilities/tool help, and rejects a revoked token. No new Bridge requirement or installer is introduced; the minimum remains 2.0.4.
- Free floating panel, Gutenberg save/reload, mocked API-provider flow, history/export/storage and settings persistence pass on WordPress 6.2/PHP 8.1 and WordPress 7.1/PHP 8.3. Published Pro Workspace is additionally checked on the upgraded 7.1 fixture. Real provider generation and new macOS hardware checks are not claimed by these tests.
- Directory package, source/attribution checks, repository guard and typecheck pass. All shipped PHP files lint on PHP 8.1.
- Plugin Check 2.1.0 retains the previously reviewed 248 low-severity submission findings; its unrestricted scan retains 248 errors and 281 warnings. These are not a claim of zero findings or WordPress.org acceptance. Human review remains required.

## Release gates

1. Review and merge the candidate source through the protected branch workflow.
2. Submit the verified directory ZIP and obtain WordPress.org approval for `pixflow-ai`.
3. Publish the approved version through WordPress.org and verify native discovery and package identity.
4. Publish the 18 matching immutable language packs while retaining existing hashes. Their isolated hosting checks are complete; availability must be checked before release.
5. Only then enable the website-to-directory handover. Legacy updaters restrict download hosts, so the handover must serve the exact approved directory ZIP through the existing Pixflow download route. Do not point those clients directly at an unaccepted external host. After that one update, the installed directory build uses native WordPress.org updates.
6. Recheck saved licences, Pro compatibility, downloads and native next-version discovery before broader rollout.

The directory candidate stays a draft until these gates are satisfied. Existing v2.0.4 releases and live update pointers must not change during preparation.
